Executive view

Overall code health: C — serviceable foundation, elevated correctness risk.

The project is readable, typed, modular, and its full check pipeline passes. That positive signal is real. It is not yet a safe release signal: the audit found several silent data-loss paths, lifecycle races at Foundry boundaries, and release tooling that can report success after skipping required work. The current tests do not exercise these paths.

The most important theme is failure integrity. Builds and migrations can report success after skipping required work, while settings transformations can silently accept and persist damaged data.

Release recommendation Hold

Resolve the three remaining High findings, add regression tests, then rebuild from a clean pack output.

Fix first

1. Make migrations transactional in outcome

Aggregate per-document errors. Never write completion flags or the migrated version when any required entity failed.

Confirmed findings

ME-15 · Legacy .db pack paths rely on Foundry compatibility normalization

public/system.json:59–135 · build/packs/

Resolved

Resolved 28 August 2026. The first eleven pack entries now use suffix-free LevelDB paths, matching the compiler output. The compiler also validates every literal build/system.json pack path after compilation; the rebuilt artifact verified all sixteen paths as directories.

Root cause: the prior manifest used the pre-v11 .db convention while compilation created suffix-free directories. It still worked because Foundry's package migration applies path.replace(/\.db$/, "") before opening a pack. That compatibility behavior originates in the documented v11 NeDB-to-LevelDB transition.

Verification: pnpm run build regenerated all sixteen packs with Foundry stopped and passed the post-build literal-path validation. Typecheck and 348 tests also pass.

HI-01 · Equipment-field ID change corrupts sibling keys

store.ts:124–143 · store.test.ts:171–203

Resolved

Resolved 28 August 2026. The reducer now keeps each non-target field under its original ID (newFields[id]) while assigning the selected field to its requested ID. The old non-target branch instead used the selected field's old ID for every sibling.

A regression test changes one field ID in a three-field category and asserts key order, all values, and referential identity for both the renamed field and its siblings. The corrected snapshot now records only the intended key replacement.

Verification: the settings-store suite passes with 41 tests and no type errors.

HI-02 · Failed entity migrations are permanently marked complete

migrateWorld.ts:35–89 · migrateCompendium.ts:33–67 · migrateWorldIfNeeded.ts:56–65

High

Actor, item, scene, and compendium-entry exceptions are caught and logged, but not propagated. The caller then writes every selected migration flag as complete; the world migration also writes the new system version and announces success.

Impact: a transient or entity-specific failure leaves a mixed-schema world that will not automatically retry. Subsequent code may assume a migration that never ran for some documents.

Fix/test: collect failures, restore pack lock state in finally, and commit completion flags only after zero failures. Show affected UUIDs and provide a retry path.

HI-03 · Locked pack databases make the build skip work with exit code 0

vitePluginCompileFvttPacks.ts:31–49

High

When locks are found, the Vite closeBundle hook prints an error-colored message and returns successfully. JavaScript and the manifest can therefore be freshly built while compendiums remain stale, missing, or left from another commit.

Impact: CI/release automation can publish an internally inconsistent artifact while reporting success.

Fix/test: throw on locks in production builds. Build packs into a staging directory, validate them, and atomically replace the destination only on success.

HI-04 · Settings import silently strips stat minimum and maximum values

statsValidator.ts:3–6 · validateImportedSettings.ts:5–13 · schemaFields.ts:24–42

High

The runtime stat shape supports optional min and required/meaningful max bounds, but the Zod import validator declares only name and default. Zod strips the undeclared properties during parsing. A settings export containing bounds therefore imports successfully with those bounds removed.

Impact: a normal export/import round trip changes PC/NPC resource behavior without warning.

Fix/test: define the full stat schema and add a round-trip invariant: import(export(settings)) must preserve all supported properties.

ME-01 · “Add equipment” ignores the selected category

pc.ts:327–343 · installEquipmentCategoryHookHandler.ts:15–28

Medium

createEquipment(categoryId) writes the obsolete system.category, while the model and pre-create hook read system.categoryId. The hook consequently falls back to the first configured category.

Fix/test: write categoryId and integration-test creation from a non-first category.

ME-02 · Valid falsy equipment values are replaced by defaults

installEquipmentCategoryHookHandler.ts:20–27

Medium

The initializer uses updateData.fields[field] ||= default. Values such as numeric zero, false, and an intentionally empty string are treated as absent and overwritten during create/import/duplicate flows.

Fix/test: default only when the property is missing or nullish; cover all supported field types and falsy values.

ME-03 · A weapon with a deleted ability crashes on attack

performAttack.ts:25–44 · WeaponMain.tsx:172–199, 246–272

Medium

The UI can render a “Not Found” configured ability, but attack controls are not disabled for that state. The handler immediately calls assertAbilityItem(ability), throwing on click.

Fix/test: disable attacks with an actionable warning or handle the missing reference before entering the roll path.

ME-04 · “Skip defeated” checks a different ordering than the active round

classicCombat.ts:402–420, 456–477

Medium

Turn indices belong to roundInfo.turns, which can be manually or round-specifically ordered. Defeat checks and the end bound instead index combatants.contents. When the orders differ, navigation can skip a living combatant, stop on a defeated one, or advance rounds early.

Fix/test: resolve each roundInfo.turns[index].combatantId to its combatant and use roundInfo.turns.length for bounds.

ME-05 · Deleting an earlier combatant changes the active turn

classicCombat.ts:193–211

Medium

After filtering deleted IDs, the code preserves the numeric index rather than the active combatant ID. For turns A/B/C with B active, deleting A leaves B/C but index 1 now selects C.

Fix/test: preserve and relocate the active ID when it survives; define explicit neighbor behavior when the active combatant is deleted.

ME-06 · Rating changes discard valid NBA-style specialities

AbilityModel.ts:245–293

Medium

The twoThreeFour mode maps rating 1 to two specialities, rating 2 to five, and higher ratings accordingly. Both rating setters truncate the array to raw newRating, not to the computed speciality count.

Fix/test: calculate the count for the prospective rating and test every mode across rating transitions.

ME-07 · Successful journal editor drops deliberately throw an error

HTMLEditor.tsx:82–120

Medium

After inserting a generated Foundry content link and focusing Monaco, the callback executes throw new Error("foo"). Every successful link drop ends as a rejected handler and can be surfaced as an unhandled error.

Fix/test: remove the debug throw and add a component test for drag-data insertion.

ME-08 · Textarea drops can suppress text or crash on world documents

TextArea.tsx:67–90

Medium

The handler prevents the default and unconditionally JSON-parses text/plain, so ordinary text drops throw and insert nothing. Its world-document branch uses legacy entity.data._id, which is not the current Foundry document access pattern and can dereference undefined.

Fix/test: parse drag data defensively, fall back to normal text insertion, and use the current document id/uuid API.

ME-09 · Turn-passing state is initialized asynchronously from a getter

turnPassingCombatant.ts:45–119

Medium

Reading passingTurnsRemaining starts an unawaited document update when the round entry is absent. Concurrent add/remove actions use zero as their absent-state base rather than defaultPassingTurns. Network completion order can persist an incorrect result.

Fix/test: keep getters pure, initialize at a defined round lifecycle point, and serialize updates or perform one atomic derived update.

ME-10 · The system socket accepts arbitrary hook names

installSocketActionHandler.ts:9–16 · typeAssertions.ts:4–12 · installNextTurnHandler.ts:9–20

Medium

Incoming messages are validated only as {hook: string, payload: array}, then dispatched via Hooks.call. There is no command allowlist, sender identity, ownership context, or per-command validation. The active GM's next-turn hook trusts the relayed request.

Impact: any connected client capable of emitting on the system socket can invoke any locally registered hook name with attacker-chosen arguments.

Fix/test: use a discriminated command union, schema-validate each payload, and authorize the requesting user against the relevant actor/combat.

ME-11 · Stat and card-category IDs can collide silently

store.ts:310–353 · utilities.ts:129–142

Medium

Stat renames do not reject an existing destination key, so one stat overwrites another. Card-category ID edits permit duplicates, making later lookup ambiguous. Equipment category/field editors already reject the equivalent collision, making this an inconsistent safety boundary.

Fix/test: centralize identifier validation and assert uniqueness after every settings reducer action and import.

ME-12 · Concurrent journal saves can lose revision history

savePage.ts:32–48 · HTMLEditor.tsx:55–64

Medium

Each page save performs a read/merge/write of the entire world-level journalMemories object. Two pages or users can read the same old value and write different entries; the last writer deletes the other history update. Debounced async saves are not queued and have no rejection handling.

Fix/test: store history per page where possible, or serialize/merge writes with revision checks. Await and surface save failures.

ME-13 · Two equipment migrations read inconsistent staged state

flaggedMigrations.ts:21–79 · migrateItemData.ts:8–16

Medium

When both migrations are pending, setEquipmentCategory writes a default to updateData.system.category; switchCategoryToCategoryId then reads the unchanged source item.system.category and writes that stale value to categoryId. The same function also contains a committed debugger statement.

Fix/test: make each migration consume staged state (or compose versioned document snapshots) and add tests for upgrades from every supported historical flag combination.

ME-14 · Settings save is non-atomic and has no failure recovery

Settings.tsx:58–69

Medium

Every setting is written concurrently with Promise.all. If one write rejects, earlier writes remain persisted, the success hook is not called, the window does not close, and no user-facing recovery explains which values changed.

Fix/test: validate the complete draft before writes, apply deterministic updates with error reporting, and either roll back from a captured snapshot or clearly report partial success.

LO-01 · The “unowned item” notifier guard is impossible

installEquipmentAddedNotifier.ts:7–16

Low

!item.parent && isPCActor(item.parent) cannot be true. World items and items on non-PC actors are not rejected as intended, so notification logic can run with no valid PC owner.

Fix/test: use !item.parent || !isPCActor(item.parent) and cover world, PC, and NPC items.

LO-02 · Turn-passing default is copied from an unrelated preset field

settings.ts:142–151 · presets.ts:57–58

Low

useTurnPassingInitiative defaults from pathOfCthulhuPreset.useNpcCombatBonuses. Both happen to be false today, so the defect is latent until preset values diverge.

Fix/test: reference the matching property and assert registered defaults equal preset defaults.

LO-03 · One QuickShock ability without a push pool gets no warning

ActiveCharacterModel.ts:204–223

Low

The warning condition requires quickShockAbilities.length > 1. The invalid and likely common case of exactly one QuickShock ability with no pool is omitted.

Fix/test: use a non-zero condition and table-test zero/one/many abilities and pools.

LO-04 · Attacks consume the hidden ammo value on non-ammo weapons

performAttack.ts:118–127

Low

The attack path always decrements ammo and does not check weapon.system.usesAmmo. Toggling ammo support on later can reveal a value drained by earlier attacks.

Fix/test: update ammo only when enabled; cover toggling and zero-ammo behavior.

LO-05 · Dice So Nice compatibility overwrites an unrelated core preference

installDSNFix.ts:3–23

Low

When a Dice So Nice setting exists, startup disables simultaneous rolls and also forces core.animateRollTable to true. The latter is unrelated to the documented compatibility change and overwrites a user preference.

Fix/test: remove the core-setting write unless a documented dependency proves it necessary; never reapply preference mutations on every startup.

The layering is understandable, but correctness concentrates at the seams: hooks mutate documents, UI reducers reshape persistent settings, and release tooling maps source packs to manifest paths. Those seams need contract tests.

What is working well

  • The complete typecheck, lint, format, test, and production-build pipeline passes.
  • Foundry DataModel schemas give persistent actor/item structures a clear home.
  • UI components and document-domain classes are mostly separated cleanly.
  • Settings registration and validation are centralized and discoverable.
  • Pure journal-memory functions have notably better behavioral test coverage.
  • Names and folder boundaries make a 38k-line TypeScript/JavaScript codebase reasonably navigable.

Test coverage shape

Vitest reports 27 executed files and 348 tests; there are 24 distinct test source files, with the workspace configuration executing three package tests in more than one project. Coverage is concentrated in pure utilities, settings/store snapshots, journal document memory, input components, and the mini-router.

Highest-value missing suites: actor/item mutation contracts, classic and turn-passing combat state machines, startup-hook behavior with mocked Foundry documents, migration failure/retry behavior, import/export round trips, socket authorization, and manifest-to-build asset validation.

HI-01 regression coverage: the former snapshot faithfully captured the wrong key transformation. It is now paired with a semantic test for key order, cardinality, values, and identity across a three-field ID change.
