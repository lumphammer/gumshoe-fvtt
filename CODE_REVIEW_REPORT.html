Executive view

Overall code health: C — serviceable foundation, elevated correctness risk.

The project is readable, typed, modular, and its full check pipeline passes. That positive signal is real. It is not yet a safe release signal: the audit found several silent data-loss paths, lifecycle races at Foundry boundaries, and release tooling that can report success after skipping required work. The current tests do not exercise these paths.

The most important theme is failure integrity. Builds and migrations can report success after skipping required work, while settings transformations can silently accept and persist damaged data.

ME-15 · Legacy .db pack paths rely on Foundry compatibility normalization

public/system.json:59–135 · build/packs/

Resolved

Resolved 28 August 2026. The first eleven pack entries now use suffix-free LevelDB paths, matching the compiler output. The compiler also validates every literal build/system.json pack path after compilation; the rebuilt artifact verified all sixteen paths as directories.

Root cause: the prior manifest used the pre-v11 .db convention while compilation created suffix-free directories. Verification: pnpm run build regenerated all sixteen packs with Foundry stopped and passed the post-build literal-path validation. Typecheck and 348 tests also pass.

HI-02 · Failed entity migrations are permanently marked complete

migrateWorld.ts:26–119 · migrateCompendium.ts:19–115 · migrateWorldIfNeeded.ts:56–65

Resolved

Resolved 28 August 2026. World, document, pack, and compendium-entry failures are now accumulated with an affected document UUID (where available) and rethrown as a single migration failure, so migrationFlags is only written when the whole run succeeds. Every registered migration was made idempotent first, which is what makes a retry safe: replay guards use already -migrated data, persistent per-document markers, cleared legacy source settings, or a one-shot combat-replacement marker.

Because migrations are idempotent, a retry simply re-runs the outstanding set over every document; documents that were already migrated produce an empty update and are skipped. There is therefore no per-document progress bookkeeping — just a migrationAttempts counter. Foundry retries once on the next GM startup, then stops trying automatically after the second failure, and a GM can retry by hand from GUMSHOE Settings > Misc, which also shows the last error.

Compendium lock state is restored in an awaited finally block, including when pack.migrate() or an individual entry update fails. The failure notification and error identify the affected migration targets.

Verification: focused tests cover a failed world actor migration (no completion write, error surfaced), multiple failing targets reported in one error, the automatic attempt cap, an explicit GM retry past that cap, and compendium lock restoration when either an entry update or pack.migrate() fails.

HI-03 · Locked pack databases make the build skip work with exit code 0

vitePluginCompileFvttPacks.ts:52–161 · vitePluginCompileFvttPacks.test.ts:52–114

Resolved

When locks are found, the Vite closeBundle hook prints an error-colored message and returns successfully. JavaScript and the manifest can therefore be freshly built while compendiums remain stale, missing, or left from another commit.

Impact: a build can be published with stale, missing, or wrong-commit compendiums while reporting success.

Resolved 28 August 2026. Production and default builds now throw when pack locks are detected. Explicit development-mode builds retain the best-effort behavior needed for local watch builds, but still validate the existing manifest paths before returning. Compilation now targets a sibling staging directory; only a fully compiled, manifest-valid pack set is promoted, with the prior output restored if promotion fails. Second-pass review · 28 Aug 2026 Confirmed, downgraded High → Medium. The mechanism is exactly as described — line 66 is a bare return after the red message, so the process exits 0. But the stated CI/release impact is not reachable for this repo: releases run through lumphammer/gh-actions on a fresh GitHub runner (.github/workflows/ci-cd.yml), where ./build/packs does not exist and no Foundry process is holding locks, so the early return never fires. The real exposure is a local production build with the world open, which is the case the red message already exists to warn about. Worth fixing so no script can be fooled; not a release-integrity hole. Note also that the ME-15 validateManifestPackPaths check sits after this early return, so it does not cover the locked-pack path.

HI-04 · Settings import silently strips stat minimum and maximum values

statsValidator.ts:3–11 · validateImportedSettings.test.ts:18–31 · schemaFields.ts:24–42

Resolved

Impact: a normal export/import round trip changes PC/NPC resource behavior without warning.

Resolved 28 August 2026. The stat import schema now declares optional numeric min and max properties, matching the published Stat type. A regression test round-trips bounded PC and NPC stats through JSON export/import and verifies that every supported property survives unchanged.

Second-pass review · 28 Aug 2026 Confirmed by execution, severity agreed. Running statsValidator.parse({ hp: { name, default, min, max } }) returns { name, default } — the bounds are stripped, as claimed. Stat declares min?/max?, both are user-editable in StatSettingsRow.tsx:176–184 and consumed as input bounds in StatField.tsx:29–30, so this is live data being silently dropped by a normal round trip. The suggested round-trip invariant test is the right shape and should cover every validator, not just stats.

ME-02 · Valid falsy equipment values are replaced by defaults

applyEquipmentFieldDefaults.ts:5–14 · applyEquipmentFieldDefaults.test.ts:5–33

Resolved

The initializer uses updateData.fields[field] ||= default. Values such as numeric zero, false, and an intentionally empty string are treated as absent and overwritten during create/import/duplicate flows.

Resolved 28 August 2026. Field initialization now copies the current values and applies defaults with nullish assignment. A regression fixture covers empty strings, numeric zero, unchecked booleans, explicit undefined, and a missing field across every supported field type.

Second-pass review · 28 Aug 2026 Confirmed. ||= treats every falsy value as absent. ME-09 · Turn-passing state is initialized asynchronously from a getter

turnPassingCombatant.ts:45–119

Medium

Reading passingTurnsRemaining starts an unawaited document update when the round entry is absent. Concurrent add/remove actions use zero as their absent-state base rather than defaultPassingTurns. Network completion order can persist an incorrect result.

Fix/test: keep getters pure, initialize at a defined round lifecycle point, and serialize updates or perform one atomic derived update.

Second-pass review · 28 Aug 2026 Confirmed; the code already admits it. There is a comment in the getter reading “this is ugly - we're calling a setter from a getter which feels bad and wrong”. ME-10 · The system socket accepts arbitrary hook names

installSocketActionHandler.ts:9–16 · typeAssertions.ts:4–12 · installNextTurnHandler.ts:9–20

Medium

Incoming messages are validated only as {hook: string, payload: array}, then dispatched via Hooks.call. There is no command allowlist, sender identity, ownership context, or per-command validation. The active GM's next-turn hook trusts the relayed request.

Impact: any connected client capable of emitting on the system socket can invoke any locally registered hook name with attacker-chosen arguments.

Fix/test: use a discriminated command union, schema-validate each payload, and authorize the requesting user against the relevant actor/combat.

Second-pass review · 28 Aug 2026 Mechanism confirmed, severity agreed, impact overstated. There is genuinely no allowlist and no sender check. But “invoke any locally registered hook with attacker-chosen arguments” reads as arbitrary write access, which it is not: most Foundry hooks are notifications rather than commands, so calling updateActor tells listeners an actor changed, it does not change one. The concrete exploitable behaviour is that any player can drive nextTurn on the active GM's client out of turn, plus whatever a listener does in response to a fabricated event. The threat model is also a player already invited to the table, not an anonymous internet caller. Medium is right and the discriminated-union fix is cheap; just don't triage it as a remote-code-execution class issue.

Medium

Each page save performs a read/merge/write of the entire world-level journalMemories object. Two pages or users can read the same old value and write different entries; the last writer deletes the other history update. Debounced async saves are not queued and have no rejection handling.

Fix/test: store history per page where possible, or serialize/merge writes with revision checks. Await and surface save failures.

Second-pass review · 28 Aug 2026 Confirmed. savePage.ts:43–47 spreads the whole world-level journalMemories object and writes it back, so the last writer wins for the entire collection.
